# Universal Ambient Light

Фоновая подсветка экрана (Ambilight) для Android. Приложение снимает экран (или наводит на
телевизор камеру устройства), берёт цвета по краям кадра и отправляет их на LED-контроллер.
Работает на Android 8.0 и новее — и на телефонах, и на Android TV.

[Read in English](README.md) · [Поддержать проект](SUPPORT.md) ·
[Лицензии сторонних компонентов](THIRD_PARTY_LICENSES.md)

## Возможности

- **Три семейства контроллеров**: Hyperion, WLED, Adalight.
- **Телефон и Android TV**: раздельные раскладки для сенсорных экранов и пультов (D-pad).
- **Захват с камеры**: снимает телевизор камерой устройства и правит перспективу по четырём
  углам — для телевизоров, где захват экрана недоступен.
- **Поиск в сети**: сканирует локальную сеть в поисках LED-серверов.
- **Настраиваемый конвейер**: качество захвата, частота кадров, сглаживание цвета, задержки.
- **Автозапуск** при включении устройства и **переподключение** после обрыва связи.
- **Режим среднего цвета**: вместо всей ленты отправляется один цвет — для слабых устройств.
- **Плитка быстрых настроек** для включения и выключения подсветки.

## Поддерживаемые контроллеры

### Hyperion
- Полная поддержка протокола Hyperion.
- Настройка приоритета сообщений.
- Совместимость со всеми версиями Hyperion NG.

### WLED
- Поддержка протоколов **DDP** (рекомендуется для WLED 0.11+) и **UDP Raw**.
- Настройка порядка цветов (RGB, GRB, BRG и др.).
- Поддержка RGBW лент.
- Управление яркостью.

### Adalight
- Поддержка протоколов **ADA**, **LBAPA** (LightBerry APA102), **AWA** (Hyperserial).
- Настройка скорости передачи (Baud Rate).
- Подключение через USB OTG.

## Системные требования

- Android 8.0 (API 26) или выше.
- Разрешение на захват экрана (MediaProjection).
- Доступ к локальной сети (для Hyperion/WLED) или поддержка USB Host (для Adalight).

## Настройка

### 1. Подключение
1. Запустите приложение и откройте **Настройки**.
2. Выберите **Тип подключения**: Hyperion, WLED или Adalight.
3. Укажите IP-адрес и порт (для сетевых контроллеров) или параметры USB (для Adalight).

### 2. Конфигурация LED
- **Конфигурация LED по сторонам**: Можно настроить каждую сторону отдельно:
    - Верх: 60 LED (по умолчанию)
    - Право: 34 LED (по умолчанию)
    - Низ: 60 LED (по умолчанию)
    - Лево: 34 LED (по умолчанию)
- **Раскладка LED**: Настройка начального угла, направления (по/против часовой стрелки) и включение/выключение отдельных сторон.

### 3. Настройки захвата
- **Источник захвата**: Выберите между режимом **Экран** (по умолчанию) или **Камера**.
    - *Экран*: Стандартный захват экрана через MediaProjection API (требует разрешения на захват экрана).
    - *Камера*: Альтернативный метод с использованием камеры устройства и коррекцией перспективы. Идеально для телевизоров без поддержки захвата экрана или для внешних телефонов.
- **Частота захвата (FPS)**: По умолчанию 30 FPS (варианты: 10, 15, 24, 30, 60).
- **Качество захвата**:
    - *Низкое (64px)* — для слабых устройств или устранения задержек.
    - *Среднее (128px)* — оптимально для большинства устройств (по умолчанию, рекомендуется).
    - *Высокое (256px)* — только для мощных процессоров.
    - *Ультра (512px)* — максимальное качество для высокопроизводительных устройств.
- **Отправлять средний цвет**: Включите для максимальной производительности (передает один цвет на всю ленту).

### 3.1. Настройка режима камеры
При использовании **Камера** в качестве источника захвата:
1. Предоставьте разрешение на **Камеру** при запросе.
2. Откройте **Настройки** → **Настройка углов камеры**.
3. Расположите устройство так, чтобы камера видела экран телевизора.
4. Перетащите четыре угловых маркера (TL, TR, BR, BL), чтобы совместить их с краями экрана телевизора.
5. Нажмите **Сохранить**, чтобы сохранить позиции углов.
6. Приложение будет использовать эти углы для коррекции перспективы во время захвата.

**Советы:**
- Используйте живое превью на главном экране для калибровки положения устройства перед запуском захвата.
- Настройка углов помогает компенсировать несимметричное расположение камеры относительно телевизора.

Кнопка **Найти телевизор** в настройке углов пытается расставить углы за вас. Четыре секунды
она смотрит на кадр: светящуюся панель от комнаты отличает по яркости, а телевизор от лампы
или окна — по тому, меняется ли картинка, — и загружает найденное в оверлей. Пока не нажата
«Сохранить», ничего не меняется. На время замера лента гаснет, иначе её собственный отсвет на
стене попадает в «экран».

Это отправная точка, а не готовая настройка: обводится светящаяся картинка, а не сама панель,
в освещённой комнате поиск путается, и углы обычно приходится поправлять руками. Если ничего
не нашлось, приложение говорит почему, а сохранённые углы остаются как были; подробная причина
пишется в logcat по тегам `AutoFrameDetection` и `CameraEncoder`.

### 3.2. Режим сна камеры
При захвате с камеры телевизор не передаёт сигнал перехода в режим ожидания, поэтому
выключенный экран продолжает передавать на ленту шум матрицы. Группа настроек **Режим сна
(камера)** (отображается только при источнике захвата **Камера**) отслеживает
откалиброванную область экрана и приостанавливает конвейер захвата, когда показывать нечего.
По умолчанию выключено.

- **Включить режим сна**: основной переключатель функции.
- **Задержка перед переходом в сон (секунды)**: сколько времени изображение должно
  оставаться тёмным перед выключением ленты. Диапазон: 5–3600 секунд, по умолчанию 120.
  Уменьшите для более быстрой реакции; увеличьте, если режим сна срабатывает на тёмных
  сценах.
- **Порог тёмного экрана (0–96)**: средняя яркость контролируемой области, при которой и
  ниже экран считается тёмным. По умолчанию: 12. Увеличьте, если выключенный телевизор не
  распознаётся.
- **Порог чувствительности к движению (1–64)**: минимальное изменение изображения, которое
  считается движением. По умолчанию: 4. Увеличьте, если шум матрицы постоянно выводит ленту
  из режима сна.
- **Переходить в сон и на статичном изображении**: также приостанавливает передачу кадров,
  если изображение перестаёт меняться (пауза видео, статичное меню); лента сохраняет
  последние цвета. По умолчанию выключено, так как продолжительная статичная сцена
  «заморозит» цвета на ленте.

В режиме сна камера остаётся привязанной, но опрашивается на частоте 5 Гц по разреженной
сетке яркости вместо полного конвейера перспективной коррекции. Для пробуждения требуются
две выборки подряд выше порога, чтобы один шумный кадр не вызвал вспышку на ленте. Все
четыре параметра можно изменять во время работы захвата, поскольку откалибровать их можно
только на живом изображении.

### 4. Сглаживание (Smoothing)
- **Включить сглаживание**: Включено по умолчанию. Рекомендуется для плавности переходов.
- **Пресет**: "Сбалансированный" (по умолчанию). Варианты: Выключено, Быстрый отклик, Сбалансированный, Плавный.
- **Время перехода**: 200 мс (по умолчанию, диапазон 50-500 мс).
- **Задержка вывода**: 80 мс (по умолчанию, диапазон 0-1000 мс). Увеличьте для синхронизации с видео (например, для Jellyfin, если светодиодная лента опережает картинку).
- **Частота обновлений**: 25 Hz (по умолчанию, варианты: 20, 25, 30, 40, 50, 60 Hz).

### 5. Запуск
1. Предоставьте разрешение на **Запись/Трансляцию экрана**.
2. Включите захват.

### Детальная настройка контроллеров

#### Hyperion
- **Host/Port**: IP сервера и порт (стандартный `19400`).
- **Приоритет**: `100` (стандартный).
- [Документация Hyperion](https://docs.hyperion-project.org/)

#### WLED
- **Host**: IP контроллера.
- **Port**: `4048` (DDP), `19446` (UDP Raw, Hyperion-вход WLED) или `21324` (UDP Raw, собственный realtime-порт WLED).
- **Протокол**: DDP (предпочтительно).
- **Цветовая схема**: Убедитесь, что порядок цветов (например, GRB) совпадает с настройками в веб-интерфейсе WLED.
- **RGBW**: работает по DDP при любой длине ленты и по UDP Raw на порту `21324` (DRGBW, до 367 светодиодов). Порт `19446` — это Hyperion-вход WLED: только сырой RGB, белого канала нет, максимум 490 светодиодов.
  Белый канал приложение считает само (общая для R, G и B составляющая уходит в W), поэтому в WLED тип ленты должен быть RGBW, а параметр **Calculate white channel from RGB** — `Manual only` либо `Dual`. В автоматических режимах WLED выбрасывает присланное значение белого и пересчитывает его из уже уменьшенного RGB, получая ноль: белые светодиоды не загораются, а цвета выглядят бледнее.
- [Документация WLED](https://kno.wled.ge/)

#### Adalight (USB)
- **Baud Rate**: `115200` (стандарт) или скорость вашей прошивки.
- **Протокол**: ADA (стандарт Arduino), LBAPA (для APA102), AWA.
- [Репозиторий Adalight](https://github.com/adafruit/Adalight)

##### Arduino скетч для Adalight

Готовый скетч для Arduino, совместимый с приложением, находится в файле [`adalight-sketch.ino`](adalight-sketch/adalight-sketch.ino).

**Быстрый старт:**

1. **Установите библиотеку FastLED:**
    - В Arduino IDE: `Инструменты` → `Управление библиотеками` → найдите "FastLED" → установите

2. **Настройте скетч:**
    - Откройте файл `adalight-sketch/adalight-sketch.ino`
    - Измените константы в начале файла:
        - `DATA_PIN` — пин для подключения LED ленты (по умолчанию 6)
        - `NUM_LEDS` — количество LED в ленте (должно совпадать с настройками в приложении!)
        - `LED_TYPE` — тип LED ленты (WS2812B, WS2811, SK6812 и др.)
        - `COLOR_ORDER` — порядок цветов (GRB для WS2812B, RGB для других)
        - `BRIGHTNESS` — яркость (0-255)

3. **Подключение:**
    - LED лента DATA → пин Arduino (по умолчанию 6)
    - LED лента VCC → 5V Arduino (или внешний источник питания для длинных лент)
    - LED лента GND → GND Arduino
    - **Важно:** Для длинных лент (>10 светодиодов) используйте внешний источник питания 5V!

4. **Загрузка скетча:**
    - Подключите Arduino к компьютеру через USB
    - Выберите плату и порт в Arduino IDE
    - Загрузите скетч

5. **Подключение к Android:**
    - Отключите Arduino от компьютера
    - Подключите Arduino к Android устройству через USB OTG кабель
    - В приложении выберите тип подключения: **Adalight**
    - Установите Baud Rate: **115200**
    - Выберите протокол: **ADA**
    - Убедитесь, что количество LED в приложении совпадает с `NUM_LEDS` в скетче

**Пример подключения WS2812B:**
```
WS2812B DATA → Pin 6 Arduino
WS2812B VCC  → 5V Arduino (или внешний 5V)
WS2812B GND  → GND Arduino
```

**Для других типов LED:**
- **APA102 (SPI)**: Используйте библиотеку FastLED с настройкой `APA102` и протокол **LBAPA** в приложении
- **WS2811**: Аналогично WS2812B, обычно `COLOR_ORDER = RGB`
- **SK6812**: Аналогично WS2812B, обычно `COLOR_ORDER = GRB`

**Устранение проблем:**
- Если LED не загораются: проверьте подключение, убедитесь что `NUM_LEDS` совпадает в скетче и приложении
- Если цвета неправильные: измените `COLOR_ORDER` (попробуйте RGB, GRB, BRG)
- Если данные не приходят: проверьте Baud Rate (должен быть 115200), убедитесь что USB OTG кабель поддерживает передачу данных

## Особенности для Android TV
Приложение оптимизировано для управления с пульта (D-pad) и отображается в лаунчере Android TV (Leanback Launcher). Для ввода IP-адресов и настроек также удобно использовать приложение "Google TV" или "Android TV Remote" на смартфоне.

## Внешнее управление (KeyMapper, Tasker, кнопки пульта)
В приложении есть прозрачная активность-переключатель — её может запускать любой инструмент автоматизации, умеющий стартовать активности, например [KeyMapper](https://github.com/keymapperorg/KeyMapper) для привязки к кнопке пульта:

- Компонент: `com.vasmarfas.UniversalAmbientLight/com.vasmarfas.UniversalAmbientLight.common.ToggleActivity`
- Без action работает как переключатель: гасит подсветку, если она запущена, иначе запускает.
- С action `com.vasmarfas.UniversalAmbientLight.action.TURN_ON` только запускает, с `com.vasmarfas.UniversalAmbientLight.action.TURN_OFF` только останавливает.

Проверка через adb:

```
adb shell am start -n com.vasmarfas.UniversalAmbientLight/com.vasmarfas.UniversalAmbientLight.common.ToggleActivity
adb shell am start -a com.vasmarfas.UniversalAmbientLight.action.TURN_OFF
```

При запуске система по-прежнему показывает диалог захвата экрана, если выбран метод захвата через MediaProjection; методы без него (Accessibility, Scrcpy/ADB, Screencap, камера) стартуют без диалога.

## Важная информация

### Для владельцев телевизоров TCL
На устройствах TCL агрессивный менеджер задач может "убивать" фоновый сервис.
**Решение:**
1. Откройте **Настройки > Приложения > Специальный доступ > Автозапуск**.
2. Разрешите автозапуск для Universal Ambient Light.
3. Либо через **"Центр безопасности"** (Safety Guard) добавьте приложение в исключения.

### Fire TV
Если на Fire TV Stick кнопка запуска ничего не делает, выдайте разрешения на наложение и захват экрана через adb. На стике включите **Параметры разработчика > Отладка ADB**, подключитесь с компьютера командой `adb connect <ip-стика>:5555` и выполните:

```
adb shell appops set com.vasmarfas.UniversalAmbientLight SYSTEM_ALERT_WINDOW allow
adb shell appops set com.vasmarfas.UniversalAmbientLight PROJECT_MEDIA allow
adb shell am force-stop com.vasmarfas.UniversalAmbientLight
```

Проверено на Fire TV Stick HD с Fire OS 7.7.1.6. Метод захвата Accessibility требует Android 11 и на Fire OS 7 (Android 9) не работает.

### Воспроизведение 4K/HDR контента
Проблема с воспроизведением видео высокого качества (2K/4K/HDR) при включенной подсветке является аппаратным ограничением многих телевизоров. Встроенные процессоры часто не справляются с одновременным декодированием тяжелого видео и захватом экрана. Это проблема, которую редко удается решить программно.

**Если вы заметили лаги или подергивание видео:**
1. Снизьте качество воспроизводимого видео до 1080p или 720p (в зависимости от возможностей ТВ).
2. Или полностью отключите подсветку в приложении на время просмотра тяжелого контента.
3. Вы можете попробовать поиграться с настройками качества захвата и FPS, но вероятность устранения проблемы невелика.

**Чёрное превью на месте видео (4K/HDR, HEVC/VP9 — или *всё* видео на некоторых ТВ):**
Если в превью Hyperion/WLED/HyperHDR на месте видео — чёрный прямоугольник, хотя меню, превью-миниатюры, фото и тестовые цвета из приложения захватываются нормально — это **не DRM**. На Android видео рисуется на отдельной **аппаратной видео-плоскости (overlay)**, которую собирает дисплейное железо в обход SurfaceFlinger; `MediaProjection` видит только то, что собрал SurfaceFlinger, поэтому область видео приходит сплошным чёрным. Обычно это касается только 4K / HEVC 10-bit / HDR10 / Dolby Vision, а обычный 1080p идёт через штатный стек — **но некоторые устройства гонят через overlay _всё_ видео** (например, ряд моделей Sony), **а на других всё зависит от кодека, а не от разрешения**: на приставках Amlogic видео в HEVC/VP9/AV1 чернеет на любом разрешении, тогда как H.264 (AVC) захватывается идеально — эти декодеры отдают AFBC-сжатые кадры сразу на видео-плоскость. Чёрный *локальный* файл исключает DRM. Это ограничение платформы — оно затрагивает любые ambient-light приложения на Android (Hyperion Android, Lightpack apps и т.д.); фикса для штатного пути `MediaProjection` нет, а методы `Scrcpy` / `Screencap` / `ADB` тоже работают после SurfaceFlinger, поэтому дают ту же чёрную область.

Обходные пути:
1. **Форсировать H.264 (AVC)**, если чернеет только HEVC/VP9/AV1: в SmartTube выбрать поток AVC вместо VP9; в Jellyfin отключить direct play для HEVC/AV1 на этом клиенте (или ограничить битрейт), чтобы сервер транскодировал в H.264.
2. **Понизить разрешение воспроизведения до 1080p** в плеере/сервере (Jellyfin → выставить max bitrate / resolution для устройства; Kodi → настройки воспроизведения; mpv → `--hwdec=no` + `--vo=gpu`). 1080p почти всегда идёт через обычную композицию.
3. **Выключить аппаратное декодирование** в плеере (Jellyfin Android: Настройки → Плеер → отключить "Prefer FMP4"; в mpv → `--hwdec=no`). Программное декодирование пускает кадр через композицию, захват возвращается.
4. **Для устройств с root** — попробовать метод захвата `Screencap (Root)` или `Screencap (Shell)` в настройках. Они идут через бинарь `screencap` вместо `MediaProjection`, что помогает при части ограничений на захват; но `screencap` тоже читает вывод SurfaceFlinger, поэтому аппаратную видео-плоскость он не вернёт.
5. **На ТВ с SoC от MediaTek** — экспериментальный метод `MTK THAL Capture` захватывает прямо из вендорского DIP-движка (до композиции), и 4K HDR там работает. Требует root и MTK-чип.

### DRM-защищенный контент
**Приложения с DRM-защитой** (такие как Netflix, Disney+, Amazon Prime Video, Кинопоиск и аналогичные стриминговые сервисы) **не будут работать** с режимом захвата экрана из-за ограничений безопасности Android. Это фундаментальное ограничение API MediaProjection в Android, которое нельзя обойти.

**Почему это происходит:**
- Android блокирует захват экрана DRM-защищенного контента для предотвращения пиратства.
- Это ограничение применяется на уровне системы и не может быть отменено приложениями.

**Решения:**
1. **Используйте режим камеры**: Переключитесь на источник захвата **Камера** в настройках. Этот метод использует камеру устройства вместо захвата экрана, поэтому работает с DRM-защищенным контентом. Вам нужно будет расположить телефон/планшет камерой к экрану телевизора.
2. **Отключите подсветку**: Выключите функцию подсветки во время просмотра DRM-защищенного контента.
3. **Используйте источники без DRM**: Смотрите контент из источников, которые не используют DRM-защиту (локальные файлы, YouTube и т.д.).

**Примечание:** Режим камеры требует правильной калибровки позиций углов для точного захвата цветов.
